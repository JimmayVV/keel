keel

A keel is the beam a hull is built on — laid first, under everything, keeping the vessel steady without ever being the boat. That is exactly what this is to Claude Code: a thin, durable layer underneath that holds your sessions steady and your setup on course.

Quick to stand up, just as quick to discard. Everything it adds rides on surfaces Anthropic documents — so it survives the platform's weekly releases, and tearing any of it out is one command that leaves no residue.

## install

Two lines inside Claude Code — vanilla or years-old setup, same two lines:

/plugin marketplace add JimmayVV/keel
/plugin install keel@keel

That is the whole install. Then, in a fresh session, let Claude walk the configuration — it inspects what's already wired and asks only about the gaps:

/keel:setup

## what's in the box

guardsEvery web and MCP result wrapped as data, never instructions — closing the indirect prompt-injection path. A security guard that blocks irreversible catastrophe and asks before exfiltration-shaped commands — and knows a Dockerfile mentioning rm -rf is text, not code. A commit guard for the trailers you never want in history.
memoryWiring for third-party memory backends over documented MCP surfaces. keel owns the interface; engines are swappable. It ships no vector store, no LLM calls, no daemon of its own.
recordAn activity log of what you asked and what was concluded, tagged by repo and branch — so research, review, and dead ends that never produce a commit are still recoverable weeks later.
skillsweek — what actually happened, from log + git + PRs. deck — say a commitment out loud today, ask “where do I stand?” tomorrow. telos — stated purpose, interrogated against revealed purpose, never injected. guide — keel explained from the live tree. setup — the install ceremony, as a conversation.
clikeel status · log · doctor · setup · settings · update · migrate — read-mostly, flags-first, idempotent writes only to keys it owns. No launcher, no wrapper, no alias: you invoke claude, exactly as you would without it.

## the rules

Own your config, buy your capabilities. Guardrails and setup are configuration — personal, a few hundred lines, correctly yours. Memory and recall are capabilities — already built better by people who do it full time. keel wires them in; it does not reimplement them.

Documented surfaces only. If Anthropic hasn't documented it, keel doesn't read, write, or parse it. The undocumented surfaces it does touch are three repairs, listed in the open with their blast radius and exit conditions — an exception stated is a debt; an exception denied is a lie.

Admission by felt need. Prose is free. A test must have caught a failure that already occurred. Runtime requires a need felt at least once, by a real user, on a real machine. This is the rule that keeps a harness from becoming a second product you maintain — the full constitution lives in the repo as two short ADRs.

## deliberately not included

  • Parsing transcripts, history files, or any undocumented format
  • A memory engine, vector store, or LLM call of its own
  • A daemon, web UI, or background service
  • Credential management

Every guard has an off-switch, every write has an undo, and the uninstall story is as documented as the install one. A layer you can't turn off is a layer you'll eventually resent.
